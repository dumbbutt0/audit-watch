## Verdict: honest negative (one sub-threshold sibling = courtesy disclosure)

### Action-smuggling fix — COMPLETE
The fix requires every action ≥4 bytes in `_hashArrayOfBytes` (forecloses `decodeCall`'s `sub(length,4)` selector-slice underflow). Critically, the hash loop computes each element's start+length identically to the `decodeCall` execute loop (`actions.offset + calldataload(i)`, `calldataload(src)`), so the signed hash commits the exact bytes execution reads → no executed action can differ from the signed set, and no unsigned action (e.g. a transfer to attacker) can be smuggled. `decodeCall`'s documented negative-offset/aliasing is harmless because the hash uses the same offsets; `AllowedSlippage` is a `memory` struct (disjoint from calldata → no aliasing corruption). Intent flow signs slippage-only BY DESIGN (onlySolver + mandatory final slippage on the signed buyToken/recipient/minAmountOut).

### Fresh BRIDGE layer — structurally safe
`BridgeSettler` is **taker-submitted, single-transaction, self-authored** (`_hasMetaTxn()==false`; metaTx reverts) → the party whose funds are pulled is always the party who authored every bridge destination/recipient/amount. No victim whose actions an attacker can author → no fund redirection. Min-out = the bridge's own user-set output. Each handler clobbers a FIXED bridge selector (only amount overridden), restricted targets blocked, callbacks blocked by the `_PAYER_SLOT` reentrancy guard → no arbitrary-call drain. Dest receiver (CrossChainReceiverFactory) is owner+Merkle/EIP-712 bound (Bailsec-audited). 2 Low hardening notes only (lingering max-approval to a fund-less router; transient-balance sweep of accidental funds — neither payable on a stateless router).

### DEX-callback siblings — clean except one sub-Medium
All pool-manager/swap callbacks (Pancake Infinity, UniV4, BalancerV3, Maverick, Dodo, Curve, UniV3 forks) are byte-exact + gated to the hardcoded vault/core/pool via the transient operator slot; no flipped-token/returndata/sellAmount-vs-permit siblings. ONE concrete sibling: **`EkuboV3.unsafeForward` (EkuboV3.sol:112)** passes call length `0x104` but writes only `0xa4` (compact encoding) → 96 bytes of uninitialized memory forwarded to the extension — a genuine Pancake-class sibling in the NEW EkuboV3 integration. **Sub-Medium / not payable:** the Settler's settlement is driven by validated returned deltas (the trailing bytes can't move funds), the extension tolerates them, but 0x DOES pay Medium $5k flat.
