# Gearbox V3.1 — Immunefi bug bounty — audit conclusion

**Target:** Gearbox V3.1 (Immunefi, $150K max, Solidity, KYC + runnable PoC, Primacy of Impact on Critical/High, scope "Last Updated 22 Jun 2026").
**Scope:** 6 repos' `contracts/` (permissionless, core-v3, oracles-v3, integrations-v3, bots-v3, periphery-v3) per `Gearbox-protocol/security/bug-bounty/v3_1-scope.md`; deployed `version` 3_10–3_20 on mainnet. ~41,600 LOC total.
**Method:** sized all 6 repos → pinned the **post-audit delta** via commit history → focused the deep pass there. 3 parallel deep-readers + manual trace of the core flow + dedup vs the Gearbox audit wall.
**Audit wall (dedup):** ChainSecurity (Core V3, Integrations, Governance, **Permissionless Apr-2025**, **V3.1-upgrade Mar-2025**, account-migration Jul-2025), ABDK (Core/Oracles V3), Decurity, MixBytes, Consensys, SigmaPrime, Nethermind, SavantChat. core-v3/permissionless saw only cleanup post-audit.

## Key finding: the post-audit delta is the Securitize / RWA integration
All meaningful post-Jul-2025 code is the **Securitize RWA integration** (integrations-v3 + periphery-v3, Apr–Jun 2026) — and the audit list shows **NO Securitize audit**, so it is fresh, complex, **un-audited** code: NAV-valued DS (regulated security) tokens, async EOA-flow redemption (gateway → per-redemption Redeemer clone → phantom token), a custom RWA liquidator, an on-demand/"monopolized" LP, and a DS-compliance NFT/registry layer. (Also a parallel Midas RWA redemption integration.)

## Verdict: no clean, payable permissionless finding (one borderline Low/Med)

| Finding | Disposition |

For collateral, valuation should be conservative. ## Submission
**One PoC-confirmed candidate** — the Securitize phantom over-valuation (`SecuritizeRedeemer.getRedemptionAmount` returns `max(...)` instead of a conservative `min`). Both a unit PoC (real contracts) and a **full-stack mainnet-fork PoC** (real Gearbox V3.1 + Securitize market via Gearbox's own attach harness) PASS — see `pocs/securitize-overvaluation/` (`SecuritizeOvervaluationPoC.t.sol`, `SecuritizeOvervaluationE2E.attach.t.sol`, `FINDING.md`). The fork PoC shows the over-valued phantom keeps an insolvent position (`twvUSD $54k ≥ debt $49,987`) **non-liquidatable** while true backing is only `$30k` → ~$20k masked pool bad debt.

**Severity = Medium (conditional High):** pool loss requires the Securitize settlement discount to exceed the LT buffer `(1 − LT) = 10%` (DS/phantom LT both 90%). Realistic redemption fees on tokenized treasuries are <1% (→ no loss), but stressed/forced redemptions or multi-day NAV drift can exceed it. The defect (wrong rounding direction; code contradicts its own "minimal" NatSpec) is real regardless. Frame for Immunefi as "optimistic phantom collateral valuation → masked insolvency / pool bad debt," pre-empting the "oracle is OOS" rebuttal (the gap is a settlement fee/haircut, NAV is unchanged in both PoCs). Submit via the user's KYC'd Immunefi account. The remaining real issues are trusted-role/OOS.
