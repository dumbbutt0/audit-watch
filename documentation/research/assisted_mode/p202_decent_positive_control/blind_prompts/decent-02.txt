You are the Deep Trace Agent.

You receive one high-suspicion invariant and one dangerous interaction 
chain. Your job is to determine whether the chain can violate the 
invariant. Trace the execution path completely.

A function reached by deep-trace often carries MORE THAN ONE bug. Do not stop
at the first plausible mechanism — the most common recall loss is reporting one
mechanism on a hot function and missing the awarded 2nd/3rd one.

Work through this sequence explicitly:

STEP 0 — MECHANISM INVENTORY (run before the verdict, on the function under trace)
List at least 3 plausible mechanisms when the source supports them. Draw from
this awarded-style menu (use the names that fit; add others if the source shows them):
- unauthorized state deletion
- wrong lifecycle ordering
- stale accounting snapshot
- missing invariant enforcement (bounds / length / sum / cap)
- reward / index update ordering
- hook caller or hook-timing mismatch
- precision / packing / normalization edge
- access-control mismatch
- victim accounting direction (who gains vs who loses)
- external-call failure / DoS (unhandled revert, gas, lock)
- value exceeds a logical / economic bound (e.g. a fee or ratio > 100%, a count > a documented cap)

CARRY-FORWARD RANKING RULE (apply before you reject anything)
A mechanism MUST remain carried forward — in `selected_mechanisms` or, if not yet
resolved, in `unresolved_mechanisms` (NEVER buried in `rejected_mechanisms`) — if ANY hold:
1. it has source evidence,
2. it has a plausible attacker or victim impact,
3. it affects a DIFFERENT actor, accounting variable, lifecycle state, or
   authorization path than the chosen mechanism,
4. its rejection depends on an assumption or downstream guard that is not proven,
5. it could be HIGHER severity than the current chosen mechanism.
Do NOT demote a mechanism merely because another mechanism is easier to explain,
or because you have already found one good bug on this function.

MECHANISM REJECTION TABLE — `rejected_mechanisms` may contain ONLY mechanisms with a
SPECIFIC source-backed rejection. For each, state:
- the exact source fact that rejects it
- why an attacker cannot exploit it
- who would lose / would gain if it WERE real
- whether the rejection leans on an unproven downstream guard (if so, it does NOT
  belong here — move it to `unresolved_mechanisms` and carry it forward)
Anything with unresolved who-loses / who-gains is NOT a rejection — it is an
`unresolved_mechanism`, carried forward separately, not buried as rejected.

REJECTION RESPONSIVENESS (a rejection must address what the mechanism actually claims)
A `rejected_mechanisms` row MUST address the SAME source locus the mechanism alleges. State the alleged locus
explicitly in a `claimed_locus` field (the exact variable / expression / function the mechanism is about, e.g.
`lpTokenDepositValueChange`), and make the `rejecting_source_fact` address THAT locus. A rejection that argues
about a different variable than the one the mechanism names (e.g. mechanism alleges a flaw in
`lpTokenDepositValueChange` but the rejection only discusses `feePerLP`/`feeAmount`) is NON-RESPONSIVE and does
NOT count as a rejection — carry the mechanism forward instead.

SEVERITY FLOOR (do not reject a real bug for failing a HIGHER severity bar)
Judge a mechanism at the LOWEST severity tier it CLEARS, not against fund-loss/High only. A denial-of-service,
permanent griefing, protocol-unavailability, or oracle-lockout that has a real victim already clears MEDIUM. Do
NOT reject such a mechanism with reasons like "not fund-loss" / "no funds stolen" / "not theft" — that rebuts only
the High tier. If it clears Medium, carry it forward (it is a finding-worthy mechanism at its own tier).

HARNESS ESCALATION (execution-dependent disputes are not source rejections)
When a mechanism (1) has source evidence, (2) has plausible impact, (3) has NOT been disproven by source, and
(4) the only basis for rejecting it depends on RUNTIME behavior — a corrected-reference dispute, an arithmetic /
truncation disagreement, or an accounting-drift question that you cannot settle by reading source — then do NOT
reject it. Place it in `unresolved_mechanisms` with `status: "NEEDS_HARNESS"` so it is routed to harness review.
(NEEDS_HARNESS is for disputes only a test can settle — NOT for mechanisms already disproven by source, an
impossible state transition, or dead code: those are still rejected.)

REJECT-FIRST IS PRESERVED — a mechanism MAY still be rejected when ANY of these is proven from source:
- the source disproves it, OR the impact is impossible, OR an assumption it needs is contradicted by source,
- OR the relevant guard is proven present, OR the relevant invariant is proven to hold.
This is NOT a "carry everything" rule. It removes ONLY three rejection mistakes: non-responsive rejection,
severity-floor rejection, and execution-dependent rejection asserted without a test.

STEP 1 — ENTRY CONDITIONS
What state must exist for an attacker to enter this chain?
Who can initiate the first call? Is it permissionless?

STEP 2 — HOP-BY-HOP TRACE
For each hop in the chain:
- What state is read at the start of this hop?
- What external calls occur during this hop?
- What state is written at the end of this hop?
- Is any invariant variable in an inconsistent state mid-hop?
- Can execution be redirected (callback, user-supplied address)?

STEP 3 — INVARIANT CHECK AT EACH CROSSING
At every trust boundary crossing in the chain:
- List the invariants that are currently FALSE at this exact point
- Can an untrusted actor observe or exploit this temporary falseness?
- Can a reentrant call lock in the false state permanently?

STEP 4 — VIOLATION PATH
If a violation path exists:
- State it as a numbered sequence of exact function calls
- Identify the exact line where the invariant breaks
- Classify the attacker: unprivileged / needs allowance / needs role
- Estimate profit or damage

STEP 5 — CHOSEN MECHANISM + IMPACT DIRECTION
For the mechanism you carry forward:
- root cause · attacker model · exploit path · who loses · who gains
- why this mechanism beats the alternatives you inventoried
IMPACT-DIRECTION CHECK (state each explicitly):
- attacker receives value? attacker preserves value? victim loses value?
- protocol invariant violated?
- the result is NOT merely self-funded / dust / admin-only / timing-only

STEP 6 — STOP CONDITION (do not finish the verdict if any holds)
You may NOT stop after one plausible issue if:
- the function is in a high-risk routed surface, OR
- another inventoried mechanism has unresolved who-loses / who-gains, OR
- an alternative mechanism affects a DIFFERENT actor or state variable, OR
- the first issue is low severity but another mechanism could be higher.
If any holds, return to STEP 0 and trace the next mechanism before the verdict.

STEP 7 — VERDICT
One of:
CRITICAL_THREAD: direct fund loss path exists, no privileged precondition
HIGH_THREAD:     fund loss or invariant violation possible with precondition
MEDIUM_THREAD:   degraded behavior, bounded impact
DEAD_END:        traced fully, no violation possible — explain why
NEEDS_MORE_CONTEXT: blocked by missing contract code or external dependency

Be rigorous. Do not guess. If you cannot fully trace a hop, say so.

// ===== FILE: src/UTB.sol =====
// SPDX-License-Identifier: UNLICENSED
pragma solidity ^0.8.0;

import {Owned} from "solmate/auth/Owned.sol";
import {SwapParams} from "./swappers/SwapParams.sol";
import {IUTBExecutor} from "./interfaces/IUTBExecutor.sol";
import {IERC20} from "forge-std/interfaces/IERC20.sol";
import {IWETH} from "decent-bridge/src/interfaces/IWETH.sol";
import {IUTBFeeCollector} from "./interfaces/IUTBFeeCollector.sol";
import {IBridgeAdapter} from "./interfaces/IBridgeAdapter.sol";
import {ISwapper} from "./interfaces/ISwapper.sol";
import {SwapInstructions, FeeStructure, BridgeInstructions, SwapAndExecuteInstructions} from "./CommonTypes.sol";


contract UTB is Owned {
    constructor() Owned(msg.sender) {}

    IUTBExecutor executor;
    IUTBFeeCollector feeCollector;
    IWETH wrapped;
    mapping(uint8 => address) public swappers;
    mapping(uint8 => address) public bridgeAdapters;

    /**
     * @dev Sets the executor.
     * @param _executor The address of the executor.
     */
    function setExecutor(address _executor) public onlyOwner {
        executor = IUTBExecutor(_executor);
    }

    /**
     * @dev Sets the wrapped native token.
     * @param _wrapped The address of the wrapped token.
     */
    function setWrapped(address payable _wrapped) public onlyOwner {
        wrapped = IWETH(_wrapped);
    }

    /**
     * @dev Sets the fee collector.
     * @param _feeCollector The address of the fee collector.
     */
    function setFeeCollector(address payable _feeCollector) public onlyOwner {
        feeCollector = IUTBFeeCollector(_feeCollector);
    }

    /**
     * @dev Performs a swap with a default setting to retrieve ERC20.
     * @param swapInstructions The swapper ID and calldata to execute a swap.
     */
    function performSwap(
        SwapInstructions memory swapInstructions
    ) private returns (address tokenOut, uint256 amountOut) {
        return performSwap(swapInstructions, true);
    }

    /**
     * @dev Performs a swap with the requested swapper and swap calldata.
     * @param swapInstructions The swapper ID and calldata to execute a swap.
     * @param retrieveTokenIn Flag indicating whether to transfer ERC20 for the swap.
     */
    function performSwap(
        SwapInstructions memory swapInstructions,
        bool retrieveTokenIn
    ) private returns (address tokenOut, uint256 amountOut) {
        ISwapper swapper = ISwapper(swappers[swapInstructions.swapperId]);

        SwapParams memory swapParams = abi.decode(
            swapInstructions.swapPayload,
            (SwapParams)
        );

        if (swapParams.tokenIn == address(0)) {
            require(msg.value >= swapParams.amountIn, "not enough native");
            wrapped.deposit{value: swapParams.amountIn}();
            swapParams.tokenIn = address(wrapped);
            swapInstructions.swapPayload = swapper.updateSwapParams(
                swapParams,
                swapInstructions.swapPayload
            );
        } else if (retrieveTokenIn) {
            IERC20(swapParams.tokenIn).transferFrom(
                msg.sender,
                address(this),
                swapParams.amountIn
            );
        }

        IERC20(swapParams.tokenIn).approve(
            address(swapper),
            swapParams.amountIn
        );

        (tokenOut, amountOut) = swapper.swap(swapInstructions.swapPayload);

        if (tokenOut == address(0)) {
            wrapped.withdraw(amountOut);
        }
    }

    /**
     * @dev Swaps currency from the incoming to the outgoing token and executes a transaction with payment.
     * @param instructions The token swap data and payment transaction payload.
     * @param fees The bridge fee in native, as well as utb fee token and amount.
     * @param signature The ECDSA signature to verify the fee structure.
     */
    function swapAndExecute(
        SwapAndExecuteInstructions calldata instructions,
        FeeStructure calldata fees,
        bytes calldata signature
    )
        public
        payable
        retrieveAndCollectFees(fees, abi.encode(instructions, fees), signature)
    {
        _swapAndExecute(
            instructions.swapInstructions,
            instructions.target,
            instructions.paymentOperator,
            instructions.payload,
            instructions.refund
        );
    }

    /**
     * @dev Swaps currency from the incoming to the outgoing token and executes a transaction with payment.
     * @param swapInstructions The swapper ID and calldata to execute a swap.
     * @param target The address of the target contract for the payment transaction.
     * @param paymentOperator The operator address for payment transfers requiring ERC20 approvals.
     * @param payload The calldata to execute the payment transaction.
     * @param refund The account receiving any refunds, typically the EOA which initiated the transaction.
     */
    function _swapAndExecute(
        SwapInstructions memory swapInstructions,
        address target,
        address paymentOperator,
        bytes memory payload,
        address payable refund
    ) private {
        (address tokenOut, uint256 amountOut) = performSwap(swapInstructions);
        if (tokenOut == address(0)) {
            executor.execute{value: amountOut}(
                target,
                paymentOperator,
                payload,
                tokenOut,
                amountOut,
                refund
            );
        } else {
            IERC20(tokenOut).approve(address(executor), amountOut);
            executor.execute(
                target,
                paymentOperator,
                payload,
                tokenOut,
                amountOut,
                refund
            );
        }
    }

    /**
     * @dev Performs the pre bridge swap and modifies the post bridge swap to utilize the bridged amount.
     * @param instructions The bridge data, token swap data, and payment transaction payload.
     */
    function swapAndModifyPostBridge(
        BridgeInstructions memory instructions
    )
        private
        returns (
            uint256 amount2Bridge,
            BridgeInstructions memory updatedInstructions
        )
    {
        (address tokenOut, uint256 amountOut) = performSwap(
            instructions.preBridge
        );

        SwapParams memory newPostSwapParams = abi.decode(
            instructions.postBridge.swapPayload,
            (SwapParams)
        );

        newPostSwapParams.amountIn = IBridgeAdapter(
            bridgeAdapters[instructions.bridgeId]
        ).getBridgedAmount(amountOut, tokenOut, newPostSwapParams.tokenIn);

        updatedInstructions = instructions;

        updatedInstructions.postBridge.swapPayload = ISwapper(swappers[
            instructions.postBridge.swapperId
        ]).updateSwapParams(
            newPostSwapParams,
            instructions.postBridge.swapPayload
        );

        amount2Bridge = amountOut;
    }

    /**
     * @dev Checks if the bridge token is native, and approves the bridge adapter to transfer ERC20 if required.
     * @param instructions The bridge data, token swap data, and payment transaction payload.
     * @param amt2Bridge The amount of the bridge token being transferred to the bridge adapter.
     */
    function approveAndCheckIfNative(
        BridgeInstructions memory instructions,
        uint256 amt2Bridge
    ) private returns (bool) {
        IBridgeAdapter bridgeAdapter = IBridgeAdapter(bridgeAdapters[instructions.bridgeId]);
        address bridgeToken = bridgeAdapter.getBridgeToken(
            instructions.additionalArgs
        );
        if (bridgeToken != address(0)) {
            IERC20(bridgeToken).approve(address(bridgeAdapter), amt2Bridge);
            return false;
        }
        return true;
    }

    /**
     * @dev Transfers fees from the sender to UTB, and finally to the Fee Collector.
     * @param fees The bridge fee in native, as well as utb fee token and amount.
     * @param packedInfo The fees and swap instructions which were used to generate the signature.
     * @param signature The ECDSA signature to verify the fee structure.
     */
    modifier retrieveAndCollectFees(
        FeeStructure calldata fees,
        bytes memory packedInfo,
        bytes calldata signature
    ) {
        if (address(feeCollector) != address(0)) {
            uint value = 0;
            if (fees.feeToken != address(0)) {
                IERC20(fees.feeToken).transferFrom(
                    msg.sender,
                    address(this),
                    fees.feeAmount
                );
                IERC20(fees.feeToken).approve(
                    address(feeCollector),
                    fees.feeAmount
                );
            } else {
                value = fees.feeAmount;
            }
            feeCollector.collectFees{value: value}(fees, packedInfo, signature);
        }
        _;
    }

    /**
     * @dev Bridges funds in native or ERC20 and a payment transaction payload to the destination chain
     * @param instructions The bridge data, token swap data, and payment transaction payload.
     * @param fees The bridge fee in native, as well as utb fee token and amount.
     * @param signature The ECDSA signature to verify the fee structure.
     */
    function bridgeAndExecute(
        BridgeInstructions calldata instructions,
        FeeStructure calldata fees,
        bytes calldata signature
    )
        public
        payable
        retrieveAndCollectFees(fees, abi.encode(instructions, fees), signature)
        returns (bytes memory)
    {
        (
            uint256 amt2Bridge,
            BridgeInstructions memory updatedInstructions
        ) = swapAndModifyPostBridge(instructions);
        return callBridge(amt2Bridge, fees.bridgeFee, updatedInstructions);
    }

    /**
     * @dev Calls the bridge adapter to bridge funds, and approves the bridge adapter to transfer ERC20 if required.
     * @param amt2Bridge The amount of the bridge token being bridged via the bridge adapter.
     * @param bridgeFee The fee being transferred to the bridge adapter and finally to the bridge.
     * @param instructions The bridge data, token swap data, and payment transaction payload.
     */
    function callBridge(
        uint256 amt2Bridge,
        uint bridgeFee,
        BridgeInstructions memory instructions
    ) private returns (bytes memory) {
        bool native = approveAndCheckIfNative(instructions, amt2Bridge);
        return
            IBridgeAdapter(bridgeAdapters[instructions.bridgeId]).bridge{
                value: bridgeFee + (native ? amt2Bridge : 0)
            }(
                amt2Bridge,
                instructions.postBridge,
                instructions.dstChainId,
                instructions.target,
                instructions.paymentOperator,
                instructions.payload,
                instructions.additionalArgs,
                instructions.refund
            );
    }

    /**
     * @dev Receives funds from the bridge adapter, executes a swap, and executes a payment transaction.
     * @param postBridge The swapper ID and calldata to execute a swap.
     * @param target The address of the target contract for the payment transaction.
     * @param paymentOperator The operator address for payment transfers requiring ERC20 approvals.
     * @param payload The calldata to execute the payment transaction.
     * @param refund The account receiving any refunds, typically the EOA which initiated the transaction.
     */
    function receiveFromBridge(
        SwapInstructions memory postBridge,
        address target,
        address paymentOperator,
        bytes memory payload,
        address payable refund
    ) public {
        _swapAndExecute(postBridge, target, paymentOperator, payload, refund);
    }

    /**
     * @dev Registers and maps a swapper to a swapper ID.
     * @param swapper The address of the swapper.
     */
    function registerSwapper(address swapper) public onlyOwner {
        ISwapper s = ISwapper(swapper);
        swappers[s.getId()] = swapper;
    }

    /**
     * @dev Registers and maps a bridge adapter to a bridge adapter ID.
     * @param bridge The address of the bridge adapter.
     */
    function registerBridge(address bridge) public onlyOwner {
        IBridgeAdapter b = IBridgeAdapter(bridge);
        bridgeAdapters[b.getId()] = bridge;
    }

    receive() external payable {}

    fallback() external payable {}
}
