# Triage — SG-002

**Status:** rejected  ·  **Severity:** Low

**ICE:** I=Low · C=High · E=Conditional

## Decision reason
Not safety-net code (guard-consistency blemish). SiloFacet.safeTransferFrom/safeBatchTransferFrom omit nonReentrant relative to transferDeposit(s).

## Follow-up packet
Inner transferDeposit nonReentrant on shared slot defends; no external callback. No action.

## Disproof
To exploit the missing nonReentrant an attacker must re-enter during the transfer, but both functions immediately route to transferDeposit, which IS nonReentrant and backed by the shared diamond reentrancy slot (s.sys.reentrantStatus); any reentry is caught by that inner guard. The functions perform no external token transfer or ERC1155 acceptance-hook callback of their own (deposits are internal accounting), so there is no callback window in which to reenter. The omission is cosmetic, not reachable.
